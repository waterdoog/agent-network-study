§ 3没能站住的：私域的返工优势

在 flash 上，触达拉平后私域在两个返工拍都领先（T2 −0.09、T4 −0.17，T2 上公域九个配对格一个都没赢）。看起来正是理论预期的位置：命名空间持久，builder 手里还留着上一版，所以返工是"改"而不是"重造"。

换成 glm-4.6 跑同一套设计，两个返工拍全部翻号。在每臂 6–9 个 episode 的样本量下，这就是噪声。诚实的表述是返工效应尚未成立——值得用 8–10 seed 去追，不值得声称。

§ 5装置本身是可信的

  • 216 个 beat 里 215 个产出了 HTML，209 个带可运行的计算器；7800 次 API 调用零失败。
  • 答案键先过参考实现校验——86 条 calc 断言，第一遍抓出 3 条我算错的，修完才允许开跑。
  • 评分链路没有模型：DOM 计数、属性值、文本存在、对 agent 自己写出的计算器跑单元测试。
  • SharedOS 真在决策：每次接触都是一次 CapabilityAuthorizer.authorize()；上跑前单独验证过 maxUses:1 第二次返回 grant_exhausted、delegationDepth:0 返回 parent_not_delegable。

§ 6下一步，按优先级

  1. matched-E0 加到每臂 8–10 seed。上面所有方向性结论都压在 6–9 上。
  2. 重做热实例，让它和冷实例共享约 40% 的事实值，而不只是共享专家——这样记忆才能省下"问"而不只是"找"。
  3. 故意从 brief 里抽掉一个必需事实，逼 builder 转包，委派深度这个旋钮才算被测过。
  4. 加一个真正一次性的授权变体，让用掉的 grant 真的挡住二次接触，内核才会拒绝东西，rework_reachable 才可能因为真实原因等于 0。

Most of the Difference Was Never the Form

Public, private and hybrid on one SharedOS kernel, a four-beat timeline, and a scorer with no model in the loop. The public arm led the cold build by 0.26 F1 — equalise reach and that collapses to 0.02.

Three sweeps: main 54 · matched-E0 27 · glm replication 18 Artifacts: 215/216 beats API failures: 0 / 7,800 calls

The one finding that holds is a negative one: 92% of what looked like "public beats private" was an artifact of roster membership, not of network form. Subtract it and what remains is too small to support a claim at this sample size — and it changes sign when the model changes.

The cold-phase public advantage falls from +0.26 to +0.02 — roughly 92% of the apparent effect was roster membership. This is a between-run comparison on one model, with a large effect and an unambiguous direction.

§ 3What did not hold: the private rework advantage

On flash, with reach equalised, private led on both revision beats (T2 −0.09, T4 −0.17; at T2 the public arm won none of nine paired cells). That is exactly where theory puts it: the namespace persists, the builder still holds the version it produced, so a revision is an edit rather than a reconstruction.

Running the identical design on glm-4.6 flips the sign on both revision beats. At six to nine episodes per arm that is noise. The honest statement is that the rework effect is not established — worth chasing at 8–10 seeds, not worth claiming.

§ 4What these runs cannot support

itemstatuswhy
Delegation depthuntestedbuilders reported nothing missing in all 324 beats, so deriveGrant was never called and parent_not_delegable never fired
Kernel refusalszeroSharedOS authorised every contact. The mechanism is wired (grant_exhausted verified before the sweep) but no configuration here made it refuse anything
Warm speedupundetectablethe warm instance replaces every fact value, so memory saves the search (one call) and not the asking (~eleven). Negative values everywhere are the design, not a finding
The T1 reach gapby designthe E allocation fixes how much each arm can reach, so a T1 gap in main is a property of the design

§ 5The instrument itself is sound

  • 215 of 216 beats produced an artifact, 209 with a working calculator; zero failures across 7,800 API calls.
  • Answer keys were checked against reference implementations first — 86 calc assertions, of which that check caught three wrong on the first pass. Nothing ran until they were right.
  • No model in the scoring loop: DOM counts, attribute values, text presence, and unit tests against the calculator each artifact must define.
  • SharedOS decides: every contact is a CapabilityAuthorizer.authorize() call; maxUses:1 returning grant_exhausted on second use and delegationDepth:0 returning parent_not_delegable were both verified directly before the sweep.

§ 6Next, in order

  1. Raise matched-E0 to 8–10 seeds per arm. Every directional statement above rests on six to nine.
  2. Rebuild the warm instance to share ~40% of its fact values with the cold one, not merely the same specialists, so memory can save asking rather than only searching.
  3. Withhold one required fact from the brief on purpose so sub-delegation is forced and the depth knob is actually tested.
  4. Add a genuinely single-use grant variant where a spent grant blocks re-contact, so the kernel refuses something and rework_reachable can be 0 for a real reason.
